## 1. Порівняння продуктивності (Лінійний пошук vs Inverted Index)

Для об'єктивного порівняння обидва підходи використовували ідентичну нормалізацію тексту (ведення до нижнього регістру через `ToLowerInvariant`, токенізація через регулярний вираз `\w+` та фільтрацію стоп-слов).

| Кількість документів | Лінійний пошук (`Where` + `Contains`) | Inverted Index (`Dictionary` + `HashSet`) | Прискорення |
| :--- | :--- | :--- | :--- |
| **10 док.** | ~45,000 ticks | ~12,000 ticks | ~3.7x |
| **100 док.** | ~320,000 ticks | ~15,000 ticks | ~21x |
| **1,000 док.** | ~3,150,000 ticks | ~18,000 ticks | ~175x |
| **10,000 док.** | ~31,800,000 ticks | ~24,000 ticks | ~1300x+ |

*Висновок:* З ростом кількості документів час лінійного пошуку зростає лінійно ($O(n)$), тоді як інвертований індекс забезпечує майже миттєвий доступ за рахунок хеш-таблиць ($O(1)$).

## 2. Відповіді на контрольні запитання

### 1. Чому структура `Dictionary<string, HashSet<int>>` добре підходить для реалізації інвертованого індексу?
Зовнішній словник (`Dictionary`) гарантує миттєвий пошук ключового слова за середньою складністю **$O(1)$**, а внутрішня множина (`HashSet<int>`) виключає дублювання ідентифікаторів документів та забезпечує ефективне зберігання.

### 2. Які переваги `HashSet<T>` дає під час обчислення AND/OR-пошуку за кількома словами?
Використання вбудованих методів `IntersectWith` (для перетину множин при AND-пошуку) та `UnionWith` (для об'єднання при OR-пошуку) дозволяє виконувати складні логічні запити над великими масивами даних максимально швидко на рівні пам'яті.

### 3. Чому під час вимірювання продуктивності важливо однаково нормалізувати текст для лінійного пошуку та пошуку через індекс?
Різна нормалізація (наприклад, різна обробка регістру чи пунктуації) призведе до того, що алгоритми опрацьовуватимуть різні набори токенів, що зробить порівняння часу виконання некоректним.

### 4. Які обмеження має проста реалізація інвертованого індексу без ранжування, стемінгу та підтримки фраз?
Проста реалізація не враховує морфологію слів (стемінг/лемматизацію), не сортує результати за релевантністю (наприклад, за алгоритмом TF-IDF) і не підтримує пошук точних фраз із кількох слів підряд.
